# 02 · 自定义图形容器格式与装载系统

译文组在 ROM 中实现了一套**自有的 VRAM 图形压缩/装载系统**，用两个 4 字节 ASCII 魔数标识（本文记为 `MAGIC1`、`MAGIC2`）。绝大部分图形资源都经它重新编码。

## 2.1 解码器 / 装载器地址（68K，均已反汇编验证）

| 地址 | 作用 |
|---|---|
| `0x4459E` | 装载入口 A（d5=1，启用像素 nibble 重映射） |
| `0x445A6` | 装载入口 B（d5=0，不重映射） |
| `0x445BA` | `cmpi.l #'MAGIC1',(a0)` —— 魔数 1 判定 |
| `0x44652` | 魔数 2 → LZ 变体分发（`jsr $44FF2`） |
| `0x44670` | 魔数 2 → **原始拷贝**变体（magic + u16 长度 + 数据） |
| `0x44682` | 装载入口 C（魔数 2 → 原始拷贝 / 魔数 1 → RLE） |
| `0x446A8` | 第三种变体：Huffman / 查表（码表建于 RAM `$E200`，构建例程 `0x4477A`） |
| `0x44638` / `0x44644` | 输出例程：4 字节打包写 VRAM（推进 / 不推进 a4） |
| `0x4474E` / `0x44758` / `0x44764` / `0x4476E` | 输出例程：含 XOR 变体（图块异或混合） |
| 目标地址 | `a4 = $C00000`（**直接写入 VRAM**） |

**调用约定**：`a0` = ROM 中的资源地址，`a4` = 目标缓冲。

## 2.2 容器 1（`MAGIC1`）格式 —— 已 100% 解码

```
偏移 0x00: 4 字节 ASCII 魔数
偏移 0x04: 控制字节流：
    c == 0x00        -> 结束（终止符）
    c in 1..0x7F     -> 从流中读取 c 个像素字节（每字节 = 2 个 4bpp 像素）
    c in 0x80..0xFF  -> 重复上一个像素字节 (c & 0x7F) + 1 次
    可选 nibble 重映射（入口 d5=1 时）：0x7→0xA，0xA→0xC，0xC→0x7（3-循环置换）

输出：4 字节 = 1 行（8 像素），32 字节 = 1 个 8×8 tile，线性写入 VRAM
```

要点：

- **变长流**。长度由终止符 `0x00` 决定，不记录在头部。原地增删数据会让后续所有偏移错位。
- **RLE 控制字节必须 ≥ 0x80**。重复 127 次是 `0xFE`，不是 `0x7E`——`0x7E` 会被解释为"接下来 126 个字节是字面量"。这是实现补丁时最容易踩的坑。
- 流开头若直接出现 RLE 控制字节，其"上一个像素字节"取 `0x00`（解码器初值）。

## 2.3 容器 2（`MAGIC2`）格式

```
变体 A（原始拷贝，例程 @0x44670）:
    4 字节魔数 + u16 长度 + 原始字节（长度需按 4 字节对齐）

变体 B（LZ 压缩，例程 @0x44FF2）:
    4 字节魔数 + 压缩流（未完全逆向）

变体 C（Huffman / 查表）:
    4 字节魔数 + 码流（码表运行时建于 RAM $E200，构建例程 @0x4477A）
```

变体 A 的解析无需解码器即可实现（见 `tools/container_tool.py` 的 `magic2_raw_decode`）。

按解码尺寸排序，内容分类：

| 类型 | 资源地址 | 解码规模 | 说明 |
|---|---|---|---|

| 字形 / 字库 | `0x0E7652` | 64 tiles | ASCII / 数字字库 |
| 字形 / 字库 | `0x16ACCA` | 116 tiles | 图形点阵 |

| 文字条 | `0x0DFD02` / `0x0DFE54` | 各 12 tiles | 两个同形、**不同调色板索引**的署名水印（详见文档 04） |
| 文字条 | `0x0F7DB0` / `0x0F7E64` / `0x0F7F12` / `0x374D7A` | 各 6 tiles | 四个难度档位名称（MODE0–MODE3） |

| UI 文字 | `0x3763E0` | 3 tiles | `END` |

**注意**：`0x0DFD02` 与 `0x0DFE54` 一度被判定为不同内容（一为署名水印、一为模式名），实际是**同一形状、不同调色板索引**的两份拷贝，且 tile 排列（行优先 / 列优先）不同。这个误判直接导致了第一版补丁失败——详见文档 04。

## 2.5 使用工具

```bash
# 填入你自己的容器魔数（十六进制）后：
python tools/container_tool.py list   --magic1 <HEX8> --rom <ROM>
python tools/container_tool.py decode --magic1 <HEX8> --rom <ROM> --offset 0x0DFE54 --out blob.bin
python tools/container_tool.py render --magic1 <HEX8> --rom <ROM> --offset 0x0DFE54 --out blob.png
```

渲染时若发现画面像"被切成竖条重新拼过"，说明该资源的 tile 排列顺序与默认不同，需要改 `wrap` 参数或按列优先重排——这不影响数据正确性，只是显示顺序。
